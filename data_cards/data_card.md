Nine relational files from the UCI Restaurant & Consumer Data collection — user profiles, payment methods, cuisine preferences, ratings, and restaurant attributes — merged into a single analysis table for causal attribution of restaurant ratings.

## Provenance

- **Source:** UC Irvine Machine Learning Repository — Restaurant & Consumer Data
- **Link:** https://archive.ics.uci.edu/dataset/232/restaurant+consumer+data
- **Snapshot:** 2012 UCI release (data collected in Mexico)
- **License / terms:** Creative Commons Attribution 4.0 International (CC BY 4.0) per UCI ML Repository terms. Citation of the original donors is required.

### Collection

Collected via a recommender-system study of restaurant consumers in Mexico. Users self-reported profile attributes (including personality, interest, and color preference items) and rated restaurants they had visited. This is a convenience sample of study participants, not a representative population sample — a limitation that carries directly into every effect estimate.

### Maintenance

Static UCI archival dataset; no updates since deposit. final_data.pkl is regenerated by re-running get_initial_data() in 01_Data_Analysis/data_pipeline.py.

## Labeling

The outcome `rating` and the mediators `food_rating` and `service_rating` are self-reported ordinal scores given by users, not expert annotations. Self-report introduces common-method bias: the same person supplies both treatment and outcome measures in a single sitting.

## Preprocessing

Nine CSVs merged with pandas left joins (user chain: userprofile -> userpayment -> usercuisine -> rating_final; restaurant chain: geoplaces2 -> chefmozaccepts -> chefmozparking -> chefmozcuisine -> chefmozhours4; combined on placeID) producing 31,559 rows x 52 features. Engineered: geodesic patron-restaurant distance (Haversine), KMeans location clusters (k=5), age groups from birth year, Jaccard cuisine-match score, and business-hours categories. '?' markers replaced with NaN, then most-frequent imputation across 17 categorical columns, then label encoding.

## Splits

No train/test split — this is estimation, not prediction. Identification comes from DoWhy backdoor adjustment on the assumed graph, with propensity-score / IPW weighting for the heterogeneous treatment effect analysis.

## Sensitive & Personal Data

Person-level attributes are used directly as treatment variables: whether the user has children (hijos), height, personality type, interest category, and color preference. Birth year is present and binned into age groups. These are individual characteristics of study participants, and several have no plausible causal mechanism on restaurant ratings — treating them as levers would be both statistically and ethically unsound.

## Recommended Uses

- Teaching causal graph construction, backdoor identification, mediation, and HTE.
- Illustrating how graph-informed estimates diverge from naive correlations.

## Discouraged Uses

- Any inference about restaurant operations outside this participant pool.
- Interpreting demographic 'treatment' effects (height, personality, color) as real — they are better read as diagnostics of residual confounding.

## Known Issues, Skews & Gaps

- Zero missing values remain across all 52 columns — because imputation has already been applied. The true pre-imputation missingness is not recoverable from this artifact, so downstream analysis cannot distinguish imputed from observed values.
- The left-join fan-out inflates row count well beyond the number of distinct ratings: 31,559 rows represent far fewer unique user-restaurant pairs, so each rating is counted multiple times. Unweighted regressions over this table implicitly weight users and restaurants by how many payment methods and cuisines they list.
- Most-frequent imputation across 17 categorical columns compresses variance and biases estimates toward the modal category.
- The causal graph derived from this table contains 53 cycles and is not a strict DAG.
